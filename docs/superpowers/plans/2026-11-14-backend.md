# Zuma Go Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать проверенный локальный backend Zuma для Godot с SQLite, отчётами и Qwen3 8B через Ollama.

**Architecture:** Один Go-процесс обслуживает HTTP, считает показатели, хранит данные и формирует отчёты. Ollama вызывается отдельным ограниченным по времени запросом. Объяснение строится в Go из разрешённых фактов, выбранных моделью.

**Tech Stack:** Go, net/http, database/sql, modernc.org/sqlite, html/template, Ollama HTTP API.

**Spec:** `docs/superpowers/specs/2026-11-14-backend-design.md` (утверждена).

## Global Constraints

- Сервер в `server/`, отдельный Go-модуль; игровой клиент не реализуется.
- По умолчанию: `127.0.0.1:8080`, `./data/zuma.db`, `http://127.0.0.1:11434`, `qwen3:8b`.
- Только локальный HTTP-интерфейс, без CORS и пользовательской авторизации.
- Протокол `reaction-memory-v1`, версия расчётов `v1`.
- Обязательные самооценка, реакция и память; сохранение одной транзакцией.
- `source`: `observed` или `synthetic`; сравнения источников раздельны.
- Тело запроса не больше 256 KiB; limit=20, максимум 100; offset>=0.
- Таймаут генерации 120 секунд; максимум одна генерация одновременно.
- SQLite/модель/сборки не попадают в Git; после установки рабочий сценарий без интернета.
- Часы исключены; диагнозов и универсального балла здоровья нет.

## Review Focus

- Нулевые значения обязательных шкал допустимы, пропущенные/null поля отклоняются (задачи 1, 4).
- Повторный запрос с переставленными ключами не создаёт новую запись; конкурентные повторы также безопасны (задача 2).
- Сессия, загруженная задним числом, меняет baseline и делает прежнее объяснение неактуальным (задачи 2, 3).
- Отмена/таймаут генерации освобождает слот и сохраняет ранее готовое объяснение (задача 3).
- HTML экранирует имена профилей; сбои модели не мешают офлайн-сценарию (задачи 4, 6).

## File Structure

- `server/go.mod`, `server/go.sum`: воспроизводимые зависимости.
- `server/internal/domain/{types,validate,report,facts}.go`: типы, проверки, расчёты и словарь фактов.
- `server/internal/store/{store,migrations}.go`: SQLite и встроенная схема.
- `server/internal/model/{client,explanation}.go`: Ollama, проверка fact_ids, конкурентность.
- `server/internal/httpapi/{api,decode,report}.go`: HTTP-контракт, JSON, HTML.
- `server/internal/config/config.go`, `server/cmd/zuma/main.go`: настройки и завершение.
- `*_test.go` рядом с компонентами: предметные, интеграционные и HTTP-тесты.
- `server/docs/openapi.yaml`, `server/examples/{client.gd,requests.ps1}`: контракт и примеры.
- `server/README.md`, `server/docs/verification.md`: запуск, ограничения, доказательства.
- `.gitignore`, `README.md`, `PLAN.md`: исключения и актуальное состояние проекта.
