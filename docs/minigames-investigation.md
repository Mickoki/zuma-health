## Подтверждённые требования пользователя

Нужны пятнашки 4×4, поиск пар с начальным показом всех карточек, математические
примеры с вариантами на время и запоминание расположения чисел с их скрытием
после первого правильного нажатия. Модуль должен подключаться к основному
приложению, работать без сервера, сохранять неотправленные результаты и
безопасно отправлять их повторно. Требуются серверные история, сравнения,
JSON/HTML-отчёты и объяснения Qwen3 8B через Ollama. Старый API сохраняется.

## Что расширяется на сервере

- SessionInput сейчас обязательно содержит survey, reaction и memory.
  Четырём новым играм нужен отдельный контракт прохождения без этих полей.
- SQLite schema version=1; нужны новые таблицы и миграция с сохранением
  существующих профилей, сессий и объяснений.
- domain.Report и domain.BuildFacts описывают старую реакцию/память.
- model.Client.Explain принимает domain.Report и сам вызывает BuildFacts.
  Для новых игр потребуется общий вход проверенных фактов с сохранением
  существующего Explain-контракта как совместимого адаптера.
- Текущий общий предел JSON-тела — 256 KiB. Лимиты событий и длительности
  новых игр должны укладываться в документированный размер запроса.
- Сравнивать результаты разных игр и разных правил/сложности напрямую нельзя;
  ключ сопоставимости должен включать game_id, rules_version и конфигурацию.

## Способы поставки модуля

1. Папка `addons/zuma_minigames/` внутри текущего Godot-проекта: собственные
   сцены, логика, ресурсы, API и demo.tscn для отдельного запуска через F6/CLI.
   Главное меню/Autoload не требуются. Для интеграции копируется одна папка,
   принимающее приложение создаёт сцену и подписывается на сигналы.
2. Отдельный Godot-проект с собственным project.godot и экспортируемой папкой
   модуля. Полностью отдельное открытие демо, но нужно дополнительно обеспечить
   единый источник ресурсов и корректный перенос в принимающий проект.

Пользователь выбрал вариант 1: `addons/zuma_minigames/`.
Число карточек, время показа, параметры арифметики, рост раундов и лимит ошибок
предложены в проекте спецификации; документ ожидает утверждения.

Пользователь дополнительно запросил случайные раскладки и повышение сложности
на 50%. В проект спецификации внесены новые параметры и точный размер
математического пространства: easy 992, normal 6042, hard 23880 выражений;
20 разных задач на прохождение. Сам модуль и новые API ещё не реализованы.

## Дополнительные проверки

- Установленный Godot поддерживает CLI `--scene`, `--headless`, `--script`,
  `--check-only`, `--quit-after`: доступны запуск демо и проверка логики движком.
- Существующий `res://server/examples/client.gd` проверен непосредственно
  Godot 4.7.2 командой `--headless --path <repo> --script
  res://server/examples/client.gd --check-only`: exit 0, ошибок типов/синтаксиса нет.
  Это проверка старого примера API, а не прохождение будущих мини-игр.
- Документация Time рекомендует монотонные get_ticks_msec/get_ticks_usec для
  длительностей; системные часы подходят только для меток календарного времени.
- FileAccess поддерживает постоянное хранение в user://, flush и close;
  остановка через F8 может оборвать запись. Очереди нужны временный файл,
  проверка результата записи и восстановление после незавершённой операции.
- DirAccess предоставляет файловые операции с кодами ошибок; ошибки записи
  и переименования нельзя трактовать как успешное сохранение.
